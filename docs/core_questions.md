# 五个核心问题与答案：行情模式识别驱动的网格门控

本文从工程与业务视角整理课题的五个核心问题。主线是：**行情模式识别是核心能力，规则门控是它的主落地链路，强化学习是同一能力之上的延伸探索，归因分析把"识别—决策—结果"串成可解释的闭环。** 每个问题都给出"为什么这样做是可行的"以及"证据在哪里"，文中数字均来自仓库当前产物（`forecast/regime/runs/`、`strategy/runs/`、`control/runs/`，22 标的，测试段 542 个标的日）。

---

## 问题一：网格策略的"不利模式"应该如何刻画？为什么定义为"低残差 + 强趋势"，而不是简单地看波动率或趋势强度？

### 业务直觉

网格赚的是"价格在一个通道里来回走"的钱：下穿买、上穿卖，一对买卖就是一次闭环利润。它亏的是"价格一路往一个方向走"的钱：只触发单边挂单，手里积累越来越多的单向持仓，最后按不利价格估值。

### 为什么是两个条件同时成立

`docs/grid_profit.md` 给出了网格收益的精确分解（$d$ 为格距、$K$ 为成交次数、$z$ 为净持仓、$\delta$ 为日终价格在最后一格内的位置）：

$$
G=\frac{d}{2}(K-z^2)+z\delta
$$

- $\frac{d}{2}K$：来回触发的**震荡收益**，成交越多越好；
- $-\frac{d}{2}z^2$：单边行情的**库存惩罚**，净持仓平方增长；
- $z\delta$：尾仓在最后一格内的位置盈亏。

这个公式说明，不利场景的本质是"$K$ 小而 $|z|$ 大"——成交少且方向一致。把它翻译成可以在 30 分钟窗口上观测的量，就得到两个条件：

| 指标 | 对应公式里的量 | 业务含义 | 阈值 |
|---|---|---|---|
| 残差宽比（价格围绕局部趋势线的波动幅度 ÷ 网格半宽） | $K$ 的代理 | 价格还在不在通道里来回穿格 | < 1.3 |
| 斜率宽比（局部趋势线斜率 × 窗口长度 ÷ 网格半宽） | $|z|$ 的代理 | 通道中心是否在单向迁移 | > 0.9 |

两者缺一不可，用 2×2 象限最容易讲清楚：

| | 斜率小（无趋势） | 斜率大（有趋势） |
|---|---|---|
| **残差大（仍在来回）** | 理想震荡市，网格最好的状态 | 高波动单边上行/下行，来回仍能闭环，网格尚可 |
| **残差小（不来回）** | 横盘缩量，成交少但也不亏，无害 | **低残差 + 强趋势：单边爬行，只触发单边挂单，网格最差** |

只看波动率会把右上角（高波动单边）误判为有利、把左下角（安静横盘）误判为不利；只看趋势会把右上角误判为不利。两个比值以"当日网格半宽"为单位，天然做了跨标的、跨价位的归一化，不需要逐标的调阈值。

### 为什么可行

- 定义来自收益公式而非拍脑袋，每个阈值都能对应到"成交次数"和"净持仓"两个可核对的业务量。
- 两个比值都只用窗口内的价格序列即可计算，无需任何外部数据，线上线下口径一致。
- 经济验证（见问题三）证明按这个定义划分出来的时段，网格收益确实单调变差。

## 问题二：事后模式标签为什么需要"粘性平滑"？平滑强弱如何影响识别器的可学习性和门控的经济价值？

### 问题出在哪

规则（残差宽比 < 1.3 且斜率宽比 > 0.9）逐分钟判定会得到一串高频翻转的 0/1：一段单边行情里可能有几分钟因为小幅回调而规则不命中，一段震荡里也可能偶尔命中。如果直接拿这串翻转当训练标签，识别器学到的是噪声，而门控按它执行就会频繁开关。

### 解决思路：把规则命中看作"带噪观测"

业务上，行情模式是一种持续一段时间的状态（一段趋势通常持续几十分钟到一两个小时），规则命中只是对这个隐藏状态的有噪声观测。于是用前向-后向平滑把它还原成连贯的事后标签，两个参数都有直接的业务解释：

| 参数 | 取值 | 业务含义 |
|---|---|---|
| 保持概率 `sticky_stay` | 0.99 / 分钟 | 状态每分钟有 99% 概率延续，隐含一段模式的期望持续时长约 100 分钟，与 A 股日内趋势的典型长度一致 |
| 观测噪声 `emission_noise` | 0.3 | 允许约 30% 的单分钟规则误报/漏报，不因一两分钟回调就判定趋势结束 |

### 平滑强度的取舍

这是一条有两头的曲线，不是越平滑越好：

- **平滑太弱**（接近原始规则）：标签翻转频繁，识别器 AUC 上不去，门控频繁开关，每次开关都要平回底仓，交易成本把收益吃掉。
- **平滑太强**：标签滞后，趋势已经开始十几分钟标签才翻，门控关晚、开也晚，错过的正是最该规避的那一段。

实测 0.99/0.3 相对此前的 0.95/0.2：经济区分度不变、测试集 AUC 从 0.652 提升到 0.695，并消除了"事后标签门控反而不如预测门控"的倒挂现象（倒挂本身就是标签质量差的信号）。

### 重要教训：不能用分类指标选平滑参数

项目中曾出现过"负期望陷阱"：某些平滑/阈值组合下识别器 AUC 更高，但门控后的收益反而更差。原因是分类指标关心每一分钟判对没有，而收益只关心"亏最多的那些时段有没有被关掉"。因此平滑参数最终按验证集门控后的经济指标选定，而不是按 AUC。

### 为什么可行

- 平滑是离线做的事后标签，只用于训练与评估，线上只用识别器输出，没有前视泄露。
- 两个参数有明确的时间尺度含义，可以和业务经验（趋势通常持续多久）互相印证。
- 参数的选择准则与最终业务目标（门控后的收益）直接对齐。

## 问题三：识别器的分类指标和门控后的经济收益之间是什么关系？为什么门控阈值 τ 用"验证段率配平"而不是分类最优点？

### 识别器现状

LightGBM 二分类，输入为 30 分钟窗口的 47 维统计特征（价格、量、盘口、ATR 等），输出不利模式概率。测试集 103,248 个分钟锚点样本、不利模式基准率 35.6%，AUC 0.700、AP 0.543。这不是一个"很准"的分类器，但问题的关键恰恰在于：**它不需要很准，只需要把"最亏的那批时段"排到前面。**

### 经济验证：把问题从"判对多少"变成"关掉了多少亏损"

`forecast/regime/economics.py` 在常开回放下，按每日不利模式占比把标的日分成三桶，比较费用后日度网格收益 $g$（测试段）：

| 不利模式占比 | 标的日数 | 平均 $g$ | 标准误 | 日均成交次数 |
|---|---|---|---|---|
| 低（0–25%） | 181 | −0.62 | 0.39 | 6.7 |
| 中（25–44%） | 181 | −4.31 | 0.98 | 12.7 |
| 高（44–100%） | 180 | −13.85 | 2.62 | 20.9 |

三桶单调恶化，高桶的亏损是低桶的 20 倍以上，且训练/验证段呈现同样的单调结构（−1.85 / −5.30 / −15.29）。这说明两件事：

1. 问题一的模式定义确实抓住了网格亏损的来源；
2. 亏损高度集中在少数时段，所以门控只要把这部分关掉，就能拿到大部分收益改善，不需要逐分钟判对。

一个容易被忽略的细节：高桶的成交次数反而最多（20.9 次/日）。这和直觉相反——趋势中成交多是因为价格一路穿格、单边不断触发，每一笔都是在加库存而不是在闭环。"成交多 ≠ 赚钱"正是网格业务的核心反直觉点，也是经济验证比分类指标更有说服力的原因。

### 为什么阈值 τ 用率配平

门控需要把概率变成开/关。分类最优阈值（如 Youden 指数）最小化的是整体错误率，但业务上两类错误的代价不对称：

- 该关没关：承受趋势亏损；
- 该开没开：损失震荡收益（机会成本），并且每次关闭要平回底仓、重新开启要重建仓位，都有摩擦成本。

率配平的做法是：在验证段选 τ，使识别器判定的"关闭占比"等于事后标签的不利模式占比（当前 τ = 0.42，测试段关闭 35,583 / 103,248 个锚点，与事后标签的 36,730 十分接近）。这样做的好处是门控的"开关节奏"被锚定到真实模式分布上，识别器的偏差只会表现为"关错了哪些时段"，不会表现为"整体过于保守或激进"。

### 统一回测的结果

测试段四种模式在同一撮合引擎、同一成本口径下对比（`strategy/runs/summary.json`）：

| 模式 | 平均 $g$ | $g$ 标准差 | 日均闭环率 | 日均成交 |
|---|---|---|---|---|
| 常开 | −6.21 | 18.68 | 0.658 | 13.5 |
| 事后标签门控（上限） | −1.92 | 10.50 | 0.649 | 8.5 |
| **识别概率门控（主链路）** | **−2.02** | **7.76** | 0.563 | 7.1 |
| RL 智能体 | −2.30 | 8.01 | 0.566 | 6.4 |

识别概率门控把平均亏损从 −6.21 压到 −2.02，已经拿到事后标签上限（−1.92）约 98% 的改善，同时收益波动从 18.68 降到 7.76，比事后标签门控还要平稳。即便识别器 AUC 只有 0.70，经济上已经足够——因为它只需要把"高桶"排到前面。

### 为什么可行

- 评价体系以业务结果（费用后 $g$、闭环率、波动）为准，分类指标只作为中间诊断。
- 阈值标定规则简单透明，可以向任何人解释"为什么今天关了这么长时间"。
- 识别器输入全部来自已发生的 30 分钟窗口，门控只在净持仓为 0 时、按分钟锚点节奏、经连续 2 拍确认后切换，线上可复现、无前视。

## 问题四：规则门控已经有效，为什么还要探索强化学习？RL 的增量到底来自哪里？

### 规则门控的结构性局限

规则门控是一个二值开关，并且为了安全只在净持仓为 0 时切换。它回答不了三个业务问题：

1. 边界状态怎么办？识别概率在 0.4 附近徘徊时，"开"和"关"都不理想，更合理的动作是"把网格收窄/放宽"而不是二选一；
2. 网格半宽固定为 $0.1\times\mathrm{ATR}_3$，但不同模式下最优半宽显然不同；
3. 开关只看识别概率一个信号，没有利用前瞻回归输出的其它信息（预期波动、预期位移等）。

### RL 不是替代模式识别，而是建立在它之上

这是本课题的定位要点。`control/` 的智能体：

- **状态**里包含 `forecast/` 的前瞻回归输出和模式识别特征——也就是说，模式识别的成果直接作为 RL 的输入；
- **动作**把 0/1 开关扩展为 7 档半宽：0 代表立即平回底仓，0.05–0.25×ATR 五档代表不同松紧的网格，极大值代表停手。规则门控的"开/关"是这个动作空间的两个端点；
- **决策节奏**固定每 10 分钟一个锚点，和规则门控一样按墙钟分钟计时。

所以 RL 回答的是"在识别出的模式下，网格应该多宽"，而不是重新发明一套模式识别。

### 现阶段的实证结论（诚实表述）

- 统一回测中 RL 平均 $g$ 为 −2.30，与识别概率门控（−2.02）处在同一水平，明显优于常开（−6.21），但尚未超过规则门控；
- RL 的平均半宽 0.010（相对价格）约为固定半宽 0.006 的 1.6 倍，成交次数最少（6.4 次/日），说明它学到的策略是"整体更保守、更宽的网格"，而不是"在边界状态上精细调节"；
- 消融对照（`control/runs/summary.csv`，单种子）：去掉 hindsight 奖励塑形（GRID-NH）、去掉前瞻特征（GRID-NA）、两者都去掉（GRID-NHNA）后，测试集总收益在 −0.004 到 −0.013 之间波动，差异在单种子噪声范围内。

因此当前对 RL 的定位是"延伸探索"：它验证了同一套模式识别成果可以作为状态输入支撑连续动作决策，并给出了与规则门控相当的结果；要证明它在边界状态上的增量，还需要多种子复跑（≥3）和按识别概率分桶的对比分析。

### 为什么这条路径仍然可行

- RL 与规则门控共用同一数据管线、特征缓存、撮合引擎与成本口径，对比是公平的，任何差异都可以归因到决策逻辑本身。
- 动作空间有明确业务含义（半宽档位），每一个决策都可以在 webviz 里逐分钟回放，不是黑盒。
- 即便 RL 最终没有超过规则门控，"RL 收敛到一个和规则门控相当的保守策略"本身也是对规则门控合理性的独立佐证。

## 问题五：归因分析要回答什么问题？它如何把"模式识别—门控决策—事后收益"串起来？

### 把归因定义成一个封闭的诊断任务

"解释市场"是开放问题，没法验收。本课题把归因收窄为：**对任意一个窗口（标的 + 日期 + 分钟段），判断门控/RL 决策与事后结果是否一致；若不一致，失败属于哪一类，主导因素是什么。**

在这套系统里，一个时段的结果不理想只可能落在三类原因：

| 类别 | 判定依据 | 业务含义 | 改进方向 |
|---|---|---|---|
| **(a) 识别错误** | 识别概率与事后标签背离（该关时概率低 / 该开时概率高） | 识别器没看出来 | 特征工程、模型 |
| **(b) 切换滞后** | 识别概率已越过 τ，但因连续确认未满 2 拍或净持仓非 0 而未切换 | 看出来了但动作慢 | 去抖参数、平仓规则 |
| **(c) 成本侵蚀** | 识别对、切换及时，但闭环率低或卖出印花税占比高 | 判断和动作都对，执行层面亏 | 半宽、成交节奏 |

这三类互斥且覆盖完整，因此归因结果可以统计、可以验收。

### Agent skill 的输入与输出

skill 接收窗口标识后，从现有产物中拉取：

- 特征轨迹（`cache/<symbol>.npz` 分钟锚点行的 47 维特征）；
- 识别概率序列与事后标签（`forecast/regime/runs/`）；
- 门控开关序列 / RL 动作与 Q 值序列（`control/trace.py`、webviz 导出）；
- 逐笔成交与成本、日度 $g$（`strategy/engine.py`、`strategy/metrics.py`）。

输出一段结构化归因：结论类别 (a)/(b)/(c)、关键时间点（概率何时越过 τ、实际何时切换、趋势何时启动）、主导特征（哪几个特征把概率推高或压低）、反事实对照（若按事后标签切换，$g$ 会是多少）。所有依据都附上可在 webviz 里定位的分钟锚点。

### 为什么用 agent 做这件事而不是写死规则

- 三类判定的**数据来源是确定的**，但判定过程需要同时读时序、读成交、读参数，并用自然语言把因果链讲给人听——这正是 agent 擅长、硬编码规则难以覆盖的部分；
- 归因的消费者是人（研究者、评审），输出需要可读、可追问，而不是再生成一张指标表；
- 每一条结论都绑定到具体数据（时间点、概率值、成交记录），agent 的输出可以被人工逐条核验，不存在"幻觉"不可控的问题。

### 归因如何反哺主链路

对测试段全部"识别概率门控 vs 事后标签门控"出现显著差距的窗口批量运行归因，统计三类占比：

- (a) 占主导 → 投入在识别器与特征；
- (b) 占主导 → 调整连续确认拍数或允许带仓切换；
- (c) 占主导 → 说明门控已接近上限，改进点在半宽与成交节奏，这正是 RL 动作空间要解决的问题。

这样归因不只是事后解释，而是决定下一轮迭代往哪里投入的依据，三条线（识别、门控、RL）在此闭合。

### 为什么可行

- 所有输入数据都已经在现有产物中，skill 只做读取、对齐与推理，不引入新的数据依赖；
- 三类判定标准是客观可核对的（概率 vs 阈值、时间差、成本占比），agent 的自由度被限制在"解释"而非"判定"；
- webviz 已经提供了逐分钟回放，归因输出可以直接指向页面上的具体位置，评审可以自行验证。

## 五个问题的内在顺序

```
定义（问题一）──→ 标签（问题二）──→ 识别与经济价值（问题三）
                                            │
                                            ├──→ 规则门控：主链路，已验证
                                            │
                                            └──→ RL 门控：延伸探索（问题四）
                                                        │
                                  归因诊断（问题五）◀───┘
                                        │
                                        └──→ 反哺 识别 / 门控 / RL 的迭代方向
```

核心能力只有一个——行情模式识别。规则门控证明它有直接的经济价值，RL 证明它可以作为更复杂决策的状态输入，归因则保证整条链路的每一个决策都能被追溯到具体数据，从而可解释、可验收、可迭代。
