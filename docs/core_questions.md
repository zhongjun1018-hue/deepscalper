# 五个核心问题（问答体）：行情模式识别驱动的网格门控

主线：**行情模式识别是核心能力，规则门控是它的主落地链路，强化学习是同一能力之上的延伸探索，归因分析把"识别—决策—结果"串成可解释的闭环。** 每个核心问题下先给主答，再列评委可能追问的子问题。文中数字均来自仓库当前产物（`forecast/regime/runs/`、`strategy/runs/`、`control/runs/`，22 标的，测试段 542 个标的日）。

---

## 一、模式定义

**Q1. 网格策略的"不利模式"应该如何刻画？为什么定义为"低残差 + 强趋势"，而不是简单地看波动率或趋势强度？**

**A.** 网格赚的是"价格在通道里来回走"的钱（下穿买、上穿卖，一对买卖是一次闭环利润），亏的是"价格一路单向走"的钱（只触发单边挂单，单向持仓越积越多，最后按不利价格估值）。`docs/grid_profit.md` 把网格收益精确分解为

$$
G=\frac{d}{2}(K-z^2)+z\delta
$$

其中 $\frac{d}{2}K$ 是来回触发的震荡收益，$-\frac{d}{2}z^2$ 是单边行情的库存惩罚，$z\delta$ 是尾仓盈亏。所以不利场景的本质是"成交次数 $K$ 小、净持仓 $|z|$ 大"。把它翻译成 30 分钟窗口上可观测的量，就是两个条件同时成立：

| 指标 | 代理的量 | 业务含义 | 阈值 |
|---|---|---|---|
| 残差宽比（价格围绕局部趋势线的波动幅度 ÷ 网格半宽） | $K$ | 价格还在不在通道里来回穿格 | < 1.3 |
| 斜率宽比（局部趋势线斜率 × 窗口长度 ÷ 网格半宽） | $\lvert z\rvert$ | 通道中心是否在单向迁移 | > 0.9 |

只看波动率或只看趋势都会误判，见 Q1.1。

**Q1.1 为什么必须两个条件同时成立，单看一个不行？**

**A.** 用 2×2 象限最清楚：

| | 斜率小（无趋势） | 斜率大（有趋势） |
|---|---|---|
| **残差大（仍在来回）** | 理想震荡市，网格最佳 | 高波动单边，来回仍能闭环，网格尚可 |
| **残差小（不来回）** | 横盘缩量，成交少但不亏，无害 | **单边爬行，只触发单边挂单，网格最差** |

只看波动率会把右上角（高波动单边）误判为有利、把左下角（安静横盘）误判为不利；只看趋势会把右上角误判为不利。真正致命的只有右下角。

**Q1.2 阈值 1.3 和 0.9 是怎么来的，换个标的还要重调吗？**

**A.** 两个比值都以"当日网格半宽"为单位，天然做了跨标的、跨价位的归一化，22 个标的共用同一组阈值。阈值按验证段门控后的经济指标选定（不是按分类指标，原因见 Q2.3），经济验证（Q3.1）证明按这组阈值划分出的时段网格收益单调恶化。

**Q1.3 这个定义为什么在工程上可行？**

**A.** 三点：定义来自收益公式，每个阈值都对应"成交次数"和"净持仓"两个可核对的业务量；两个比值只用窗口内价格序列即可计算，不依赖外部数据，线上线下口径一致；经济验证给出了独立于分类指标的证据。

## 二、事后标签

**Q2. 事后模式标签为什么需要"粘性平滑"？平滑强弱如何影响识别器的可学习性和门控的经济价值？**

**A.** 规则（残差宽比 < 1.3 且斜率宽比 > 0.9）逐分钟判定会得到高频翻转的 0/1：单边行情里几分钟小回调就不命中，震荡里也会偶尔命中。直接拿它当标签，识别器学到的是噪声，门控照它执行会频繁开关。业务上行情模式是一种持续几十分钟到一两小时的状态，规则命中只是对这个隐藏状态的带噪观测，所以用前向-后向平滑把它还原为连贯的事后标签。平滑强度是两头都不能走极端的取舍（Q2.2），当前参数 0.99/0.3 按验证段经济指标选定（Q2.3）。

**Q2.1 两个平滑参数有业务含义吗，还是纯调参？**

**A.** 都有直接解释：

| 参数 | 取值 | 业务含义 |
|---|---|---|
| 保持概率 `sticky_stay` | 0.99 / 分钟 | 状态每分钟 99% 概率延续，隐含一段模式的期望持续约 100 分钟，与 A 股日内趋势典型长度一致 |
| 观测噪声 `emission_noise` | 0.3 | 容忍约 30% 的单分钟规则误报/漏报，不因一两分钟回调就判定趋势结束 |

**Q2.2 平滑是不是越强越好？**

**A.** 不是。平滑太弱接近原始规则：标签翻转频繁、识别器 AUC 上不去、门控频繁开关，每次开关都要平回底仓，成本吃掉收益。平滑太强则标签滞后：趋势已开始十几分钟标签才翻，门控关晚开也晚，错过的正是最该规避的一段。实测 0.99/0.3 相对此前的 0.95/0.2：经济区分度不变、测试集 AUC 从 0.652 提升到 0.695，并消除了"事后标签门控反而不如预测门控"的倒挂（倒挂本身就是标签质量差的信号）。

**Q2.3 平滑参数为什么不按 AUC 选？**

**A.** 项目中出现过"负期望陷阱"：某些平滑/阈值组合 AUC 更高，门控后的收益反而更差。原因是分类指标关心每一分钟判对没有，而收益只关心"亏最多的那些时段有没有被关掉"。因此平滑参数按验证段门控后的经济指标选定，AUC 只作为中间诊断。

**Q2.4 平滑用了未来信息，会不会前视泄露？**

**A.** 不会。前向-后向平滑只在离线生成事后标签时使用，用于训练和评估；线上只用识别器对已发生 30 分钟窗口的输出，不接触标签。

## 三、识别与经济价值

**Q3. 识别器的分类指标和门控后的经济收益之间是什么关系？为什么门控阈值 τ 用"验证段率配平"而不是分类最优点？**

**A.** 识别器是 LightGBM 二分类，输入 30 分钟窗口 47 维统计特征，测试集 103,248 个分钟锚点、不利模式基准率 35.6%，AUC 0.700、AP 0.543——不算"很准"。但它不需要很准，只需要把"最亏的那批时段"排到前面，因为经济验证表明亏损高度集中（Q3.1）。τ 用率配平是因为两类错误代价不对称、分类最优点与业务目标不一致（Q3.3）。统一回测证明识别门控已拿到事后标签上限约 98% 的改善（Q3.4）。

**Q3.1 怎么证明模式定义真的和亏损相关？**

**A.** `forecast/regime/economics.py` 在常开回放下，按每日不利模式占比把标的日分三桶，比较费用后日度网格收益 $g$（测试段）：

| 不利模式占比 | 标的日数 | 平均 $g$ | 标准误 | 日均成交 |
|---|---|---|---|---|
| 低（0–25%） | 181 | −0.62 | 0.39 | 6.7 |
| 中（25–44%） | 181 | −4.31 | 0.98 | 12.7 |
| 高（44–100%） | 180 | −13.85 | 2.62 | 20.9 |

三桶单调恶化，高桶亏损是低桶的 20 倍以上，训练/验证段同样单调（−1.85 / −5.30 / −15.29）。这说明模式定义抓住了亏损来源，且亏损集中在少数时段——门控只要关掉这部分，就能拿到大部分改善。

**Q3.2 高桶的成交次数反而最多，不是成交越多越赚吗？**

**A.** 这是网格业务的核心反直觉点。趋势中成交多是因为价格一路穿格、单边不断触发，每一笔都在加库存而不是闭环，对应公式里 $K$ 增加的同时 $z^2$ 增加得更快。"成交多 ≠ 赚钱"也是经济验证比分类指标更有说服力的原因。

**Q3.3 为什么阈值 τ 不用 Youden 之类的分类最优点？**

**A.** 分类最优点最小化整体错误率，但业务上两类错误代价不对称：该关没关要承受趋势亏损；该开没开损失震荡收益，而且每次关闭要平回底仓、重开要重建仓位，都有摩擦成本。率配平是在验证段选 τ 使识别器判定的"关闭占比"等于事后标签的不利模式占比（当前 τ = 0.42，测试段关闭 35,583 / 103,248 个锚点，事后标签为 36,730）。这样门控的开关节奏被锚定到真实模式分布，识别器的偏差只表现为"关错了哪些时段"，不会表现为整体过于保守或激进，也让"今天为什么关了这么久"可以向任何人解释。

**Q3.4 门控最终效果如何？**

**A.** 测试段四种模式在同一撮合引擎、同一成本口径下对比（`strategy/runs/summary.json`）：

| 模式 | 平均 $g$ | $g$ 标准差 | 日均闭环率 | 日均成交 |
|---|---|---|---|---|
| 常开 | −6.21 | 18.68 | 0.715 | 13.5 |
| 事后标签门控（上限） | −1.92 | 10.50 | 0.765 | 8.8 |
| **识别概率门控（主链路）** | **−2.02** | **7.76** | 0.720 | 7.4 |
| RL 智能体 | −2.30 | 8.01 | 0.814 | 7.4 |

识别门控把平均亏损从 −6.21 压到 −2.02，拿到事后标签上限约 98% 的改善，且波动从 18.68 降到 7.76，比事后标签门控还平稳。AUC 0.70 在经济上已经足够。

**Q3.5 线上执行口径是什么，有没有前视？**

**A.** 识别器输入全部来自已发生的 30 分钟窗口；门控只在净持仓为 0 时、按分钟锚点节奏、经连续 2 拍确认后切换；ATR 用此前 3 个完整交易日预计算，当日恒定。全部可复现、无前视。

## 四、强化学习

**Q4. 规则门控已经有效，为什么还要探索强化学习？RL 的增量到底来自哪里？**

**A.** 规则门控是二值开关，且为安全只在净持仓为 0 时切换，回答不了三个问题：识别概率在 0.4 附近徘徊的边界状态怎么办；半宽固定为 $0.1\times\mathrm{ATR}_3$，但不同模式下最优半宽显然不同；开关只用识别概率一个信号，没用上前瞻回归的其它输出。RL 不是替代模式识别，而是建立在它之上（Q4.1）。现阶段 RL 与规则门控相当、尚未超越，定位为延伸探索（Q4.2）。

**Q4.1 RL 和模式识别是什么关系？**

**A.** `control/` 的智能体：状态里包含 `forecast/` 的前瞻回归输出与模式识别特征，即模式识别的成果直接作为 RL 输入；动作把 0/1 开关扩展为 7 档半宽（0 = 立即平回底仓，0.05–0.25×ATR 五档，极大值 = 停手），规则门控的"开/关"是这个动作空间的两个端点；决策节奏固定每 10 分钟一个锚点，与规则门控同样按墙钟分钟计时。RL 回答的是"在识别出的模式下网格应该多宽"，而不是重新发明一套模式识别。

**Q4.2 RL 现在的结果到底怎样？**

**A.** 如实表述：统一回测中 RL 平均 $g$ 为 −2.30，与识别门控（−2.02）同一水平，明显优于常开（−6.21），但未超过规则门控。RL 平均半宽 0.010（相对价格）约为固定半宽 0.006 的 1.6 倍，成交最少（6.4 次/日），说明它学到的是"整体更保守、更宽的网格"，而非在边界状态上精细调节。消融（`control/runs/summary.csv`，单种子）去掉 hindsight 奖励塑形、去掉前瞻特征、两者都去掉后，测试集总收益在 −0.004 到 −0.013 间波动，差异在单种子噪声范围内。要证明 RL 在边界状态上的增量，还需多种子（≥3）复跑和按识别概率分桶的对比。

**Q4.3 既然没超过规则门控，这条路径还有什么价值？**

**A.** 三点：RL 与规则门控共用同一数据管线、特征缓存、撮合引擎与成本口径，对比公平，差异可归因到决策逻辑本身；动作空间有明确业务含义（半宽档位），每个决策都能在 webviz 里逐分钟回放，不是黑盒；"RL 收敛到一个与规则门控相当的保守策略"本身是对规则门控合理性的独立佐证。

## 五、归因分析

**Q5. 归因分析要回答什么问题？它如何把"模式识别—门控决策—事后收益"串起来？**

**A.** "解释市场"是开放问题无法验收，所以把归因收窄为：**对任意窗口（标的 + 日期 + 分钟段），判断门控/RL 决策与事后结果是否一致；若不一致，失败属于哪一类、主导因素是什么。** 在这套系统里失败只可能落在三类互斥且覆盖完整的原因（Q5.1），因此归因结果可统计、可验收，并反过来决定下一轮投入方向（Q5.4）。

**Q5.1 三类失败原因是什么？**

**A.**

| 类别 | 判定依据 | 业务含义 | 改进方向 |
|---|---|---|---|
| (a) 识别错误 | 识别概率与事后标签背离 | 识别器没看出来 | 特征工程、模型 |
| (b) 切换滞后 | 概率已越过 τ，但因连续确认未满 2 拍或净持仓非 0 而未切换 | 看出来了但动作慢 | 去抖参数、平仓规则 |
| (c) 成本侵蚀 | 识别对、切换及时，但闭环率低或卖出印花税占比高 | 判断和动作都对，执行层面亏 | 半宽、成交节奏 |

**Q5.2 Agent skill 的输入输出是什么？**

**A.** 输入窗口标识后，从现有产物拉取：特征轨迹（`cache/<symbol>.npz` 分钟锚点行 47 维）、识别概率与事后标签（`forecast/regime/runs/`）、门控开关序列 / RL 动作与 Q 值序列（`control/trace.py`、webviz 导出）、逐笔成交与成本、日度 $g$（`strategy/engine.py`、`strategy/metrics.py`）。输出结构化归因：结论类别 (a)/(b)/(c)、关键时间点（概率何时越过 τ、实际何时切换、趋势何时启动）、主导特征、反事实对照（若按事后标签切换 $g$ 会是多少），每条依据附可在 webviz 定位的分钟锚点。

**Q5.3 为什么用 agent 而不是写死规则？会不会有幻觉？**

**A.** 三类判定的数据来源是确定的，但判定过程要同时读时序、读成交、读参数，并把因果链用自然语言讲给人听——这是 agent 擅长、硬编码规则难以覆盖的部分；归因的消费者是人，输出需要可读、可追问。幻觉可控是因为 agent 的自由度被限制在"解释"而非"判定"：三类判定标准是客观阈值（概率 vs τ、时间差、成本占比），每条结论绑定到具体时间点、概率值、成交记录，可逐条人工核验。

**Q5.4 归因怎么反哺主链路？**

**A.** 对测试段全部"识别门控 vs 事后标签门控"差距显著的窗口批量归因，统计三类占比：(a) 占主导 → 投入识别器与特征；(b) 占主导 → 调整连续确认拍数或允许带仓切换；(c) 占主导 → 门控已接近上限，改进点在半宽与成交节奏，这正是 RL 动作空间要解决的问题。归因由此不只是事后解释，而是迭代方向的依据，识别、门控、RL 三条线在此闭合。

**Q5.5 归因在工程上为什么可行？**

**A.** 所有输入都已在现有产物中，skill 只做读取、对齐与推理，不引入新数据依赖；webviz 已提供逐分钟回放，归因输出可直接指向页面位置，评审可自行验证。

## 五个问题的内在顺序

```
定义（Q1）──→ 标签（Q2）──→ 识别与经济价值（Q3）
                                   │
                                   ├──→ 规则门控：主链路，已验证
                                   │
                                   └──→ RL 门控：延伸探索（Q4）
                                               │
                          归因诊断（Q5）◀───────┘
                                │
                                └──→ 反哺 识别 / 门控 / RL 的迭代方向
```

核心能力只有一个——行情模式识别。规则门控证明它有直接的经济价值，RL 证明它可以作为更复杂决策的状态输入，归因保证每一个决策都能追溯到具体数据，从而可解释、可验收、可迭代。
